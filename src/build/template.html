The face of the system

A pizza tracker for buildings

Domino's earned trust with a tracker. You watch the pizza move and nobody has to call the store. Owners deserve that same view of their capital projects. In Yurt 8, every project lives on one chronological tracker, and every stage is wired directly to the data sources that matter for it. It is not a status slide somebody made on Friday. It is the live state of the work.

The engine

Review. Generate. Learn. Repeat.

The tracker is the face. This loop is the engine behind it. Three moves that feed each other, speaking one shared language, getting a little smarter on every pass.

01

Review

Real time visibility into everything already moving. No waiting for a meeting to find out.

  • Live feeds of working Revit models and CAD files
  • Standardized spreadsheets showing the critical numbers
  • RFIs and submittals translated into plain English for the owner
  • Clashes surfaced as they occur, not at the milestone review
  • Flags avoidable slowdowns and the design issues that become change orders
  • Predicts issues from patterns it has seen before
02

Generate

Design moves in seconds instead of weeks. Built from my proven generative design work on live programs.

  • Deterministic algorithms set the guardrails
  • LLMs generate options inside those guardrails, connected through MCP
  • Then deterministic checks again. Gates alternate, always
  • Test fits and sizing with no third party fees for non wet seal work
  • Runs in a browser through Autodesk Design Automation. Nobody needs Revit installed
  • Swap cabinets, re-size MEP, re-wire redundant power, keep every asset number
03

Learn

Every review and every generation makes the next one better. The system never stands still.

  • AWS Bedrock agents tied to S3 data lakes
  • Every pass sends coordinates, parameters, and useful data to the lakes
  • Knowledge bases gated by review: deterministic, probabilistic, human, or all three
  • Tied to the rules, codes, and standards Hut 8 and its vendors flag as critical
  • Grows from stakeholder input and exemplar designs fed in as standardized JSON

One JSON format ties all three together

Review writes it. Generate reads it and writes it back. Learn grows from it. Same coordinates, same parameters, same distance relationships, same patterns. Nothing gets translated between steps, so nothing gets lost between steps.

{
  "asset": "CRAC-B2-07",
  "coordinates": [412.5, 96.0, 14.2],
  "parameters": { "make": "VendorA", "model": "CR-30", "cooling_kw": 30 },
  "relationships": [
    { "to": "CAB-B2-ROW3", "type": "serves", "distance_ft": 18.5 }
  ],
  "pattern": "2N-cooling-loop",
  "stage": "fit-out",
  "written_by": "review"
}

Working quietly underneath

The boring parts, kept deliberately boring

The plumbing below is where digital delivery programs usually die: too clever, too heavy, too proud of themselves. Every choice here is the simple version on purpose.

ACC, used two different ways

External vendors live in Autodesk Construction Cloud for day to day design work. It is their world and they are good at it. For Hut 8, ACC is deliberately treated as a limited tool: a data source we mine through its APIs, with the bells and whistles kept away. Owners do not need forty modules. They need the tracker.

Vendors get a simplified experience too: sensible permissions, clean folders, nothing to fight with.

A folder structure nobody has to hate

ISO 19650 compliant, using ACC's own framework, four folders deep. That is the whole thing.

HUT8-[PROJECT]
├─ 01-WIP        each vendor's working area, their eyes only
├─ 02-SHARED     coordinated models, checked and clash reviewed
├─ 03-PUBLISHED  approved for construction, read only
└─ 04-ARCHIVE    every superseded version, kept automatically

Files move left to right only, and each move is a gate the system checks. Vendors keep working the way they already work.

ISO 19650 without the ceremony

The standard earns its keep in exactly one place here: every asset gets one ID at design and keeps it for life. That ID is the same name in the model, in the JSON schema, on the physical tag, and in the sensor feed. The versions of ISO 19650 that get lauded at conferences and never survive contact with an American job site are exactly what this is not.

Sensors reporting to the same brain

IoT monitoring of assets and sites (CSSM) feeds the Operations stage of the tracker through the same JSON schema. Temperature, power, vibration, door state: the building reports on itself the way projects report on themselves. Autodesk Tandem is an interesting reference point for digital twins. This is the simpler version: same IDs, same schema, live data, no second platform to maintain.

The stack, in one breath

  • ACC APIs mine files, models, issues, and versions from the CDE
  • Procore, Tableau, Power BI, and Microsoft Project connect through their own APIs for cost and schedule truth
  • Autodesk Design Automation runs Revit work in the cloud, no install
  • MCP connects deterministic tools to LLM reasoning, in alternating gates
  • AWS Bedrock agents over S3 data lakes do the learning

The plan

Twenty four months, reported monthly in dollars and days

Build the tool, build the team, then maintain and scale both. Every month closes with one page for leadership: dollars moved, days moved, and which scenario the data came from, whether alpha, beta, or live. If a month cannot show both numbers, that month failed and I will say so plainly.

How this was built

One orchestrating AI agent, directed by me, driving specialized sub agents: a research crew that pulled and cross checked Hut 8's public filings, drafting agents held to my voice rules, and adversarial reviewers that attacked every claim before it shipped. Deterministic checks gated the probabilistic steps, in alternating layers.

That is not just a build method. It is the same architecture Yurt 8 runs on. I build with the pattern I am recommending, because it works.

Take the AI away and I still build this

HTML, Python, C#, C, and the .NET framework are home turf, on top of a computer science foundation and years of boots on the ground program delivery. The AI made this faster. It did not make it possible. That distinction matters when you are deciding who to trust with a system like this.
